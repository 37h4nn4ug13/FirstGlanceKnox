# Decisions and assumptions

1. The supplied master prompt is the product specification. The user's direct instruction substitutes temporary media URLs for real project photos/videos; the original supplied JPEG is preserved unchanged at `static/brand/logo.jpg`.
2. This is a local Django build. No remote repository, hosted Site, production email, customer outreach, payment provider or paid integration is authorized. Nothing is deployed.
3. Python 3.13 and Django 5.2 LTS; dependencies are frozen after installation. PostgreSQL is the required production database. This computer has no PostgreSQL or Docker executable, so the runnable local preview uses SQLite. Concurrency guarantees require the documented PostgreSQL validation before launch.
4. A small set of apps keeps one authoritative schema: accounts, operations, marketing and portal. Operations groups CRM, estimating, jobs, billing and compensation with explicit domain services.
5. Plain Django templates and small JavaScript modules avoid a frontend build dependency. ReportLab generates PDFs on Windows without a GTK installation; the equivalent HTML remains the accessible document.
6. No public phone, email, prices, reviews, years of experience, insurance claims or service coverage beyond Knoxville is invented. Configure verified facts and approved photos before public release. Temporary images are design references, not claimed company work.
7. Local email uses a file backend. Queued delivery remains visible and can be drained locally; production uses Celery/Redis and deliberately configured providers.
8. Cleaner pay is a fixed accepted assignment snapshot payable on admin-approved completion; sales commission snapshots earn only on full invoice payment. These are separate ledgers and record payments without executing payroll.
9. September 9 continuation: retain the existing visual design and focus on usable staff navigation and administrator appointment changes. Reuse the domain services for rescheduling, cancellation, and withdrawal instead of duplicating state changes in views. A no-op reschedule is rejected to preserve accepted agreements.
10. The mobile workspace uses a native disclosure menu with the same role-aware navigation fragment as desktop. It remains usable without JavaScript; JavaScript adds Escape and outside-click dismissal.
11. Staff browser tests run on a separate Django test database and server. No browser test changes the existing demo records. Browser automation is authorized by the adopted master prompt's responsive verification requirements.
12. Private portal responses use `Referrer-Policy: same-origin`: cross-origin requests omit the private URL, while native same-origin form submissions retain the origin required by Django CSRF checks. `no-referrer` was reproduced as causing `Origin: null` and HTTP 403 for customer estimate approval/decline. Anonymous shared-link browser regressions cover both decisions; enforced-CSRF tests retain missing-token and foreign-origin rejection.
13. The manuals-driven improvement pass adds Staff management to the workspace. Removal means deactivation, not deletion. Deactivation invalidates passwords/sessions and pending invitations, disables push, releases open lead assignments and upcoming cleaner offers, and flags in-progress work for administrator handoff without changing that work's pay agreement. Rehire requires a fresh invitation/password. Self-lockout and edits to protected owners by nonowners are rejected.
14. Unaccepted estimates are corrected by explicit revisions rather than overwriting an existing document. The original remains in history, its links are revoked, and the replacement must be reviewed/sent/accepted separately. Custom lines and price overrides go through existing approval rules. Accepted/billed work remains outside this revision workflow.
15. Recurring plans now support editing, pause/resume, and explicit generation in the local preview. A submitted visit timestamp prevents a stale double-click from generating the following recurrence. Existing jobs are unchanged when a plan is edited or paused. Availability changes reject conflicts with already-booked work.
16. Email deliveries exposes the estimate/invoice outbox and explicit processing/retry. Obsolete estimate messages are blocked after revision/revocation. Local delivery still writes files; this does not enable production email. Invitation delivery failures are handled on the employee page and can be retried with a fresh invitation.
17. The device outbox now supports review/discard and blocks sign-out while pending updates exist. Synchronization re-reads storage after each response so leads added during an in-flight request are retained. Edits to rejected updates and more complex offline recovery remain future work.
